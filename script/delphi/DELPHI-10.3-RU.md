# Embarcadero Delphi 10.3 Rio: границы поддержки

Полная совместимость с Delphi 10.3 Rio **не подтверждена**. Проверки Free Pascal
и Lazarus не проверяют компилятор Embarcadero, VCL, FireMonkey или формат отладочной
информации Rio. Этот документ задаёт условия приёмки именно Delphi 10.3.

## Версия и среда

Для проверки необходима лицензированная установка Windows с точным номером
обновления 10.3.x, редакцией продукта, установленными SDK и зависимостями проекта.
Сохраняйте версию `dcc32`/`dcc64`, путь к `rsvars.bat` и журнал MSBuild вместе с
результатами. Типичный каталог Rio — `Embarcadero\Studio\20.0`; один путь сам по
себе не доказывает версию компилятора. Helper пока не проверяет версию BDS.

Редактор на macOS/Linux может отправлять сборку на Windows по SSH. Это требует
существующей копии проекта и зависимостей на Windows: транспорт не синхронизирует
исходники и не устанавливает компилятор. Поддержка ОС редактором не означает
поддержку этой ОС компилятором Rio.

В [официальной матрице Rio](https://docwiki.embarcadero.com/RADStudio/Rio/en/Supported_Target_Platforms)
указаны отдельные цели Windows, macOS, iOS, Android и Linux; VCL относится к
Windows. Astra Linux и Apple Silicon в этой матрице не указаны. Доступность цели
зависит от обновления Rio, редакции и SDK. Для Linux-графики требуется отдельно
проверить [FireMonkey for Linux](https://docwiki.embarcadero.com/RADStudio/Rio/en/FireMonkey_for_Linux).
Успешная сборка LCL под Astra не подтверждает совместимость FMX.

## Что реализовано и что ещё требуется

| Возможность                  | Текущее состояние                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Редактирование Object Pascal | Нативная грамматика, подсветка и структура; не доказательство полной семантики Rio.                                                                     |
| `.dproj`, `.groupproj`       | `build.py --tool delphi` вызывает MSBuild `/t:Build` с Config/Platform после импорта `rsvars.bat`. Реальная сборка Rio не проверена.                    |
| Clean/Rebuild/Deploy         | `--msbuild-target` выбирает Clean/Rebuild/Deploy. Реальное выполнение Rio и развёртывание через SDK/PAServer не проверены.                              |
| Пакеты `.dpk`                | Прямой вход `.dpk` не поддерживается; пакет должен иметь `.dproj`. Зависимости групп, runtime BPL/DCP и установка design-time пакетов требуют проверки. |
| Отладка                      | Подключается внешний MCA DAP по stdio. Конкретные Win32/Win64 артефакты Rio, переменные и исключения ещё не проверены.                                  |
| Семантика и Code Insight     | Штатного DelphiLSP в 10.3 нет. `pasls` анализирует Free Pascal, а не точную семантику Rio.                                                              |
| Формы VCL/FMX                | Визуального дизайнера DFM/FMX, палитры компонентов и инспектора объектов нет.                                                                           |

LSP Code Insight появился в
[Delphi 10.4](https://docwiki.embarcadero.com/RADStudio/Sydney/en/What%27s_New).
Инструкция по подключению DelphiLSP из более новой версии не закрывает поддержку
классического Code Insight Rio. Нельзя обещать такую совместимость переносом
исполняемого файла из другой установки.

[README MCA на закреплённой ревизии](https://github.com/csm101/delphi-visual-studio-code-debugger/blob/599d4bf04b14daee91b7606c18b0b1df2098f5b8/README.md)
указывает Delphi 10.3 Rio или новее и настройки символов для Win32/Win64.
Это заявленная совместимость upstream, а не результат нашей приёмки. Для проверки
нужны соответствующие исходникам EXE, подробный MAP и RSM; без RSM полноценная
инспекция переменных не обеспечивается. Профиль Zed не заменяет движок отладчика.

## Приёмка на лицензированной установке

Для каждого пункта сохраняются версия IDE/компилятора/адаптера, проект, команда,
лог и наблюдаемый результат. Проверки должны запускаться из установленной сборки
Zed, а не только из отдельного терминала.

- [ ] Обнаружить именно Rio, импортировать его `rsvars.bat`, проверить пути с
      пробелами и отсутствие подмены другой установленной версией Delphi.
- [ ] Собрать и запустить консольный и VCL-проект: Win32 и Win64, Debug и Release.
      Проверить ресурсы, unit aliases, search paths, условные defines и Unicode.
- [ ] Собрать `.groupproj` с зависимым runtime-пакетом; проверить порядок сборки,
      BPL/DCP, повторную сборку и диагностируемую ошибку отсутствующей зависимости.
- [ ] Внести синтаксическую ошибку: сборка завершается неуспешно, диагностика
      приводит к правильному файлу и строке, предыдущий EXE не запускается как новый.
- [ ] Отладить Win32 и Win64: подтверждённая точка останова, шаги, стек, локальные
      строки, объекты, массивы, generics, watches, потоки и исключения.
- [ ] Проверить attach, остановку и повторный запуск; старые MAP/RSM не должны
      выдавать правдоподобные, но неверные значения.
- [ ] Повторить сборку и отладку с редактора macOS/Linux через Windows-транспорт:
      сопоставление путей, точки останова, обрыв соединения и завершение процесса.
- [ ] Проверить семантические переходы, completion, rename и диагностику на API
      RTL/VCL/FMX Rio. Подсветка и успешная сборка не засчитываются за этот пункт.
- [ ] Для заявления о полной IDE реализовать и проверить визуальное редактирование
      DFM/FMX: открыть форму, изменить свойство/событие, сохранить и собрать без
      потери компонентов и ресурсов.
- [ ] Для каждой обещанной FMX/мобильной/Linux-цели отдельно проверить SDK,
      развёртывание, запуск и отладку; для Astra указать точный выпуск и архитектуру.

## Работа без Windows и лицензии

Можно реализовывать обнаружение версий, выбор целей MSBuild, проверку конфигурации,
сопоставление путей и тесты транспорта на фикстурах. Можно готовить `.dproj`,
`.groupproj` и тестовые исходники с ожидаемыми результатами. Эти проверки не
подтверждают совместимость компилятора или отладчика.

Полноценная семантика Rio и визуальный дизайнер остаются самостоятельными
незавершёнными возможностями. До выполнения соответствующей приёмки релиз нельзя
обозначать как «полная поддержка Delphi 10.3»; рабочие FPC/Lazarus сценарии должны
быть описаны отдельно.

## Выбор цели MSBuild

`--tool delphi --msbuild-target Build|Clean|Rebuild|Deploy` передаёт ровно одну
цель MSBuild. Без флага сохраняется `Build`. `--run` разрешён только для
`Build`/`Rebuild`; `Clean`/`Deploy` не запускают исполняемый файл. Сам `Deploy`
не подразумевает предварительную сборку. Доступность цели и параметры
развёртывания определяются проектом и установленными инструментами Rio.

Флаг запрещён для Free Pascal и Lazarus. Ограничения проверяются и для
JSON-запросов Windows-хоста. Тесты команд и отклонения неверных запросов
проверены локально; реальные цели Rio требуют лицензированной Windows-среды.
